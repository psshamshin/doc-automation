# AGENTS.md — doc-automation (LUNA POINT 2)

Задача: по артефактам разработки (ченджлог фронта, дифф кода lerna, задачи Jira) обновить
документацию LUNA POINT 2 (руководство пользователя и администратора, RU и EN) и написать
release notes. Эксперимент: база — дока 2.2.0, результат сравнивается с докой 2.3.0.

Правила отбора и классификации (группы А-З) с историей изменений: `docs/RULES.md`. Настройки правил: `config/rules.json`.

## Что уже сделано кодом (шаги 1–2)

`python3 -m pipeline.run --config config/release-2.3.0.json` создаёт в `runs/2.3.0/`:

| Файл | Что внутри |
| --- | --- |
| `report.md` | Читать первым. Все единицы изменения с решениями и причинами |
| `05_units.json` | Главный вход. Единица = задача GUI-xxxx: строки ченджлога, файлы кода, строки UI, Jira, решения по правилам, кандидаты разделов, упоминания старых текстов в доке |
| `02_code_diff.json`, `code/patches/*.diff` | Все изменённые файлы lerna и их патчи |
| `03_i18n_diff.json` | Какие тексты интерфейса появились, исчезли, изменились (ru, en) |
| `02_reachability.json` | Файлы, достижимые из `apps/point` (граф импортов) |
| `06_docs_index.json` | Индекс базовой доки: заголовки, картинки, include, термины |
| `output/MD_rus/docs`, `output/MD_eng/docs` | Копия текстов доки 2.2.0. **Править только здесь** |
| `output/screenshots.md`, `output/trace.md` | Заготовки списка скринов и трассировки |

Решение `decision.action` в `05_units.json`:
`doc_and_rn` — описать в доке и RN; `rn_and_check_doc` — строка RN и проверить, не описывает ли дока ошибочное поведение;
`rn_and_check_langs` - локализация (Д9): строка RN и проверить список языков в доке, другие разделы не править;
`review` — правила не решили, решает агент по коду; `screenshot_check` — только визуальные правки; `skip` — отброшено.

## Что делает агент (шаги 3–6)

Порядок и инструкции — в `prompts/`:

1. `prompts/03_analyze.md` → `runs/2.3.0/07_analysis.json` — по патчам и строкам UI понять, что изменилось на экране; решить `review`-единицы; уточнить класс Д.
2. `prompts/04_locate.md` → `runs/2.3.0/08_plan.json` — где в доке править (файл, абзац, действие).
3. `prompts/05_write.md` → правки в `runs/2.3.0/output/MD_rus` и `MD_eng`, метки скринов, `screenshots.md`, `trace.md`.
4. `prompts/06_release_notes.md` → `runs/2.3.0/output/MD_{rus,eng}/docs/release-notes/230.md`.

Схемы результатов — в `schemas/`. Шаг 7 (сравнение с эталоном) запускает человек:
`python3 -m pipeline.run --config config/release-2.3.0.json --steps etalon,compare`.

## Запреты

- **Не читать эталон** до шага 7: `luna-point-2.3.0/`, `runs/*/_etalon/`, `runs/*/compare/`. Иначе эксперимент не имеет смысла.
- Не изменять входные папки: `lerna-*`, `luna-point-*`, `jira/`.
- Не трогать ES/PT и другие языки — их переводит существующий джоб `translate-diff`.
- Не выдумывать. Факт берётся только из кода, ченджлога, Jira. Нет факта — вопрос в `trace.md` и `07_analysis.json` (`open_questions`), а не догадка.

## Правила написания (группы Ж и З)

- Ж1. Сначала RU, затем EN с тем же смыслом.
- Ж2. Названия элементов интерфейса — дословно из файлов переводов нужного языка (`03_i18n_rows.json`, поле `new`), в кавычках, как принято в доке («…» в RU, "…" в EN).
- Ж3. Названия продуктов и компонентов — только через переменные доки (`{{PRODUCT_NAME}}` и т.п., см. `variables` в `06_docs_index.json`). Без жёстких «LUNA» и «VisionLabs» в новом тексте.
- Ж4. Стиль как в соседних абзацах: безлично, повелительно для инструкций («Нажмите…»), таблицы полей в принятом формате.
- Ж5. Минимальная правка: незатронутый текст не переписывать.
- Ж6. Каждая правка — строка в `output/trace.md` с задачей и правилами.
- Ж7. Если текст раздела лежит в `includes/`, править include-файл.
- Ж8. Release notes: структура как в предыдущем файле (`release-notes/220.md`), одна строка на задачу, язык пользователя, без имён компонентов и номеров задач.
- З1–З5. Если изменение затрагивает экран, который есть на скрине в доке, перед ссылкой на картинку ставится метка:

```markdown
!!! warning "SCREENSHOT-TODO GUI-4104"
    Переснять: раздел «Мониторинг», раскрытое главное меню.
    Причина: изменены группировка и названия пунктов меню.

![Раздел "Мониторинг"](../Imgs/image141.png)
```

и строка в `output/screenshots.md`. Старую ссылку на картинку не удалять (сборка не должна ломаться), кроме случая удалённой функции (З4).
