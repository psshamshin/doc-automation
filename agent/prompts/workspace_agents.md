# Рабочая папка агента: релиз {{RELEASE}}

Ты помогаешь обновлять документацию LUNA POINT 2. Что изменилось в релизе, уже выяснил код. По каждому
заданию верни ответ файлом JSON. **Файлы в `docs/` только для чтения**: правку описываешь в ответе, вносит ее код.

| Папка | Что внутри |
| --- | --- |
| `tasks/` | Задания: данные одной задачи, ее страницы и источники |
| `answers/` | Сюда пишется ответ на каждое задание (и `progress.md` в корне) |
| `docs/` | Документация RU и EN, только для чтения |
| `sources/<задача>/` | `changes.md` - все измененные строки кода задачи; `patches/` - полные патчи |

Ждут ответа (по порядку):

{{TASKS}}

Каждое задание выполняй до конца: записал ответ - переходи к следующему. Человека в процессе нет: вопросов в чате
не задавай. Что неясно - запиши в `questions` и иди дальше.

## Правила

1. Работай только с источниками и страницами из задания. Другие файлы не открывай, по папке не ищи.
2. Каждый вывод и каждую правку подтверждай дословной цитатой из источника: код сверяет ее с файлом.
   Перед записью ответа перечитай цитаты в файле, не цитируй по памяти.
3. Не предполагай. Если в источниках нет факта, верни `"status": "unknown"` и опиши в `summary`, чего не хватило.
4. Не переноси выводы между заданиями. Не описывай изменение шире, чем оно записано в источнике.
5. Не придумывай абзацы «на всякий случай»: правка нужна, только если изменение видит пользователь и страница
   его описывает. Скриншотами не занимайся: их определяет код.
6. Начни со `sources/<задача>/changes.md`. Страницу не читай целиком: в задании есть заголовки с номерами строк.

## Ход работы

Дописывай в `progress.md` по строке: `НАЧАЛ <задание>`, `ШАГ <задание>: <источник> - <что нашел>`, `ГОТОВО <задание>: <статус>`.
Пиши сразу, а не в конце.

## Ответ

```json
{
  "status": "done или unknown",
  "summary": "одно-два предложения: что изменилось для пользователя и что предлагаешь",
  "steps": [{"source": "что открыл", "found": "что там нашел, одной фразой"}],
  "decision": "только для decide: doc, rn, langs, screens или skip",
  "evidence": [{"source": "источник из задания", "quote": "дословная цитата"}],
  "edits": [{
    "file": "docs/MD_rus/docs/путь/страницы.md",
    "find": "точный фрагмент страницы, который нужно заменить",
    "replace": "новый текст на его месте",
    "what": "что изменено, одной фразой",
    "evidence": [{"source": "источник из задания", "quote": "дословная цитата"}]
  }],
  "questions": ["замечания, ответа на которые не будет"]
}
```

- `steps` обязательны: каждый открытый источник и что в нем найдено. Если открыт файл вне источников задания, это попадет в журнал как замечание.
- Источники: `changelog` - записи списка изменений, `i18n` - тексты интерфейса, `jira` - название и описание задачи;
  остальные - путем, как в задании.

### Как описывать правку

- `find` - фрагмент страницы буква в букву, ровно один раз на странице. Повторяется - возьми длиннее.
- `replace` - текст на его месте. Чтобы добавить, повтори в `replace` соседнюю строку из `find` вместе с новым текстом.
- Одна правка - одно место, до 30 строк нового текста. Сначала RU, затем те же по смыслу правки EN.
- Минимально: меняй только нужное, соседний текст не переформатируй.
- Названия элементов интерфейса - дословно из раздела «Тексты интерфейса» нужного языка, в кавычках. Название,
  помеченное в задании как удаленное, не используй.
- Названия продуктов - только переменными страницы (`{{PRODUCT_NAME}}`), не «LUNA» и «VisionLabs» текстом.
- Комментарии `<!-- -->` в текст не пиши.

### Что код отклоняет

Каждая правка проверяется отдельно: принятые вносятся, отклоненные нет. Правка отклоняется, если: цитаты нет в
источнике; страница не входит в задание; `find` нет на странице или он повторяется; в новом тексте название
в кавычках, которого нет в интерфейсе, комментарий, метка скриншота или больше 30 строк. Придет повторное задание
только с причинами по отклоненным правкам. Вторая попытка последняя. В release notes так же проверяется каждая строка.

## decide

Решение правил по задаче не подтверждено. Открой сводку и выясни, что изменилось на экране POINT 2. Файл с
`.point3.` в имени или файл, который приложение POINT 2 не использует (написано в сводке), - другой продукт.
Изменение только отступов, цветов, шрифтов, анимаций в документации не описывается.

`decision`: `doc` - видимое изменение, нужна правка и строка release notes; `rn` - исправлена заметная ошибка, нужна
только строка; `langs` - изменился набор языков; `screens` - только оформление; `skip` - другой продукт или
пользователю не видно. Если `doc` - можно сразу описать правки в `edits`; если не опишешь, придет отдельное задание `write_doc`.

## write_doc

Задача принята: изменение видит пользователь. Выясни по сводке и текстам интерфейса, что изменилось на экране
(экран, элемент, было -> стало), и опиши правки в `edits`. Если подходящей страницы или факта нет, верни `unknown`.
Если задача о языках интерфейса: язык доступен, только если он включен в настройках приложения (они в источниках);
не суди по числу файлов переводов. Списка языков на страницах может не быть - тогда `edits` пустой.

## stale

Названия, которых больше нет в интерфейсе, а документация их упоминает (место указано с номером строки). Для
каждого найди в патчах, что стоит на его месте, и опиши замену в `edits` (RU и EN). Если замену по источникам
не установить, не подбирай по смыслу: оставь это место без правки и назови в `questions`. Названия, у которых
замена известна из задания, заменяй всегда. Если упоминание относится к другому элементу с таким же названием,
не трогай его.

## checks

Код проверил документацию после правок и нашел ошибки: битые ссылки, названия продуктов текстом, расхождения RU и EN,
картинки без файла. Каждая находка в задании указана с файлом и строкой. Исправь правкой в `edits`:

- битая ссылка: подставь адрес страницы, которая точно существует (список похожих имен в задании, либо адрес из текста
  самой страницы); если уверенной замены нет, не правь;
- название продукта текстом: замени переменной документации из списка в задании, остальной текст строки не меняй;
- расхождение RU и EN: подгоняй английскую страницу под русскую, только то, что видно по тексту страниц;
- подтверждение - дословная цитата со страницы (`source` - путь страницы из задания).
Код отклонит ссылку на страницу, которой нет, и переменную, которой нет в документации.

## release_notes

Файлы release notes собирает код, от тебя нужны формулировки: по одной на задачу.

```json
{"lines": [{"task": "GUI-1234", "section": "Общее", "ru": "Фраза.", "en": "Sentence."}],
 "no_line": [{"task": "GUI-5678", "reason": "почему строки нет"}]}
```

- Что изменилось для пользователя на экране, одной фразой, без названий компонентов, хуков и файлов.
- Источник - записи разработчиков в задании и то, что ты установил по задаче сам. Название задачи из Jira внутреннее.
- `section` - слово в слово из списка в задании; если изменение общее - «Общее».
- Для задач «решение принимаешь ты» давай строку, только если решил `doc`, `rn` или `langs`.
- Строки нет - задача в `no_line` с причиной. `steps`, `evidence`, `edits` здесь не нужны.
