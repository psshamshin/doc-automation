# Рабочая папка агента: релиз {{RELEASE}}

В этой папке лежит только то, что нужно для заданий. Работай только с ней.

| Папка | Что внутри |
| --- | --- |
| `tasks/` | Задания. Каждое выполняется отдельно, в каждом свой список разрешенных источников |
| `answers/` | Сюда записывается ответ на каждое задание |
| `docs/` | Рабочая копия документации RU и EN, `trace.md`, `screenshots.md` |
| `sources/<задача>/` | Патчи и файлы кода одной задачи |

Порядок заданий:

{{TASKS}}

Этот файл - общие правила для всех заданий. В самих заданиях только данные конкретной задачи.

## Правила работы с источниками

1. Работай только с тем, что перечислено в конце задания в разделах «Страницы документации этой задачи» и
   «Разрешенные источники». Другие файлы не открывай и не ищи по папке: все, что относится к задаче, уже
   найдено и дано тебе.
2. Каждое утверждение и каждую правку подтверждай дословной цитатой из разрешенного источника. Код
   проверит, что цитата буква в букву есть в источнике. Ответ без подтверждения или с цитатой, которой в
   источнике нет, не принимается, а правки из него отклоняются.
3. Не объясняй и не предполагай. Если в источниках нет факта, не выводи его из общих знаний, из названий
   файлов или из других заданий: верни `"status": "needs_human"` и вопрос в поле `questions`.
4. Не переноси выводы между заданиями. Что изменено в задаче, определяют только ее записи, ее патчи и ее
   тексты интерфейса.
5. Не описывай изменение шире, чем оно записано в источнике. Если в источнике «исправлен порядок пунктов
   меню», в документации меняется порядок пунктов меню, и ничего больше.
6. Если тебя спрашивают о том, чего нет в источниках задания, отвечай: «В источниках задания этого нет».
   Не придумывай причину и не меняй файлы в ответ на вопрос. Файлы меняются только по заданию.
7. Менять можно только страницы из раздела «Страницы документации этой задачи», файлы `docs/trace.md`,
   `docs/screenshots.md` и свой файл ответа. Правка в любом другом файле будет отклонена.

## Как проверяется твоя работа

Код сверяет ответ с реальными данными. Ответ не принимается, а правки отклоняются, если:

- цитаты в `evidence` нет в названном источнике буква в букву;
- в `steps` назван файл, которого нет среди источников и страниц задания;
- изменена страница, которой нет в задании, или изменение не названо в `edits`;
- в новом тексте есть название элемента интерфейса в кавычках, которого нет ни в текстах интерфейса, ни
  на странице, ни в записях задачи. Названия бери только из раздела «Тексты интерфейса» задания;
- изменено больше 12 строк на одну заявленную правку: правка должна быть минимальной;
- в ответе нет кода правил.

Поэтому перед тем как записать ответ, перечитай каждую цитату в источнике и убедись, что она стоит там
дословно. Не цитируй по памяти.

## Ответ

Ответ обязателен. Запиши его в файл, названный в задании, в формате JSON:

```json
{
  "item": "номер задания",
  "rules": "{{RULES_CODE}}",
  "status": "done или needs_human",
  "summary": "одно-два предложения: что сделано или что выяснено",
  "steps": [
    {"source": "что открыл: источник или страница из задания", "found": "что там нашел, одной фразой"}
  ],
  "evidence": [
    {"source": "источник из списка разрешенных", "quote": "дословная цитата из него"}
  ],
  "edits": [
    {
      "file": "docs/MD_rus/docs/путь/страницы.md",
      "what": "что изменено: было -> стало",
      "evidence": [{"source": "источник из списка разрешенных", "quote": "дословная цитата"}]
    }
  ],
  "files_changed": ["все файлы, которые ты изменил"],
  "questions": ["вопросы человеку, если есть"]
}
```

- `steps` - обязательный журнал: каждый открытый источник и что в нем найдено, по порядку. Записывай шаг
  сразу, как открыл файл, а не в конце по памяти. По шагам человек увидит, откуда взялся вывод и где ошибка.
  Шаг со ссылкой на файл вне источников задания делает ответ непринятым.
- `evidence` на верхнем уровне обязательно для задания «проверить решение».
- `edits` обязательно, если ты менял страницы: одна запись на каждую правку, у каждой свое подтверждение.
- Источник `changelog` означает записи списка изменений задачи, `i18n` - ее тексты интерфейса, `jira` -
  название и описание задачи. Остальные источники указываются путем, как в списке.
- `rules` - код из этого файла: `{{RULES_CODE}}`. Он показывает, что ты прочитал общие правила. Без него ответ не принимается.

## Вид задания `decide`: Проверить решение и сразу выполнить его

Решение правил по задаче не подтверждено. В задании записи, основание для проверки и источники.

1. Открой патчи из списка источников и выясни, что изменилось на экране приложения POINT 2.
2. Проверь продукт: если изменение есть только в файлах с `.point3.` в имени, это другой продукт.
3. Проверь видимость: изменение только отступов, цветов, шрифтов и анимаций в документации не описывается.
   Изменение текста, элементов, порядка действий или поведения - видимое.
4. Выбери одно решение и добавь его в ответ полем `decision`:
   - `doc` - видимое изменение POINT 2: нужна правка документации и строка в release notes;
   - `rn` - исправлена ошибка, которую мог заметить пользователь: только строка в release notes;
   - `langs` - изменился набор языков интерфейса;
   - `screens` - изменилось только оформление: текст не менять, проверить скриншоты;
   - `skip` - другой продукт или пользователь изменения не видит.
5. В `summary` напиши, что изменилось для пользователя (экран, элемент, было -> стало) или почему задача
   отброшена. В `evidence` приведи цитаты из патчей или записей, на которых основан вывод.
6. Второго задания по этой задаче не будет, поэтому доведи ее до конца в этом же ответе:
   - решил `doc` - внеси правку по разделу «Вид задания `write_doc`» и перечисли ее в `edits`;
   - решил `langs` - выполни раздел «Вид задания `check_langs`»;
   - решил `rn`, `screens` или `skip` - документацию не меняй.

Если по источникам решить нельзя, верни `needs_human` с вопросом и документацию не меняй.

## Вид задания `write_doc`: Написать правку документации

Задача принята: изменение видит пользователь, документацию нужно поправить.

1. По патчам и текстам интерфейса из источников выясни, что изменилось на экране: экран, элемент,
   было -> стало. Пиши только то, что видно в источниках.
2. Найди место на страницах из раздела «Страницы документации этой задачи». Если раздел подключается через
   `{% include %}` и нужного файла в списке нет, не ищи его сам: верни `needs_human`.
3. Внеси правку в RU (`docs/MD_rus/...`), затем ту же по смыслу в EN (`docs/MD_eng/...`).
4. Если на странице есть скриншот затронутого экрана, поставь перед ним метку и добавь строку в
   `docs/screenshots.md`:

   ```markdown
   !!! warning "SCREENSHOT-TODO <номер задачи>"
       Переснять: что именно.
       Причина: что изменилось.
   ```

5. На каждую правку добавь строку в `docs/trace.md`: задача, язык, файл, что изменено.
6. Файл release notes не трогай: для него есть отдельное задание.

Как писать:

- Правка минимальная: незатронутый текст не переписывай. Стиль как в соседних абзацах.
- Названия элементов интерфейса бери дословно из раздела «Тексты интерфейса» нужного языка, в кавычках,
  как принято на странице.
- Названия продуктов и компонентов пиши только переменными, которые уже есть на странице
  (например, `{{PRODUCT_NAME}}`). Не пиши «LUNA» и «VisionLabs» текстом.
- Старую ссылку на картинку не удаляй.

Если подходящего места нет или не хватает факта, текст не выдумывай: верни `needs_human` с вопросом.

## Вид задания `check_doc`: Проверить документацию после исправления ошибки

Задача - исправление ошибки. В документации нашлись старые тексты интерфейса (места указаны ниже).

1. Открой указанные места на страницах этой задачи.
2. Если страница описывает старое, ошибочное поведение или старое название, поправь ее (RU, затем EN) и
   добавь строки в `docs/trace.md`. Каждую правку подтверди цитатой из источников.
3. Если страница уже описывает правильное поведение или упоминание относится к другому элементу, ничего не
   меняй и напиши это в `summary`.

## Вид задания `check_langs`: Сверить список языков интерфейса

В задаче из задания менялась локализация.

1. По файлам настроек приложения из списка источников выясни, какие языки интерфейса доступны пользователю
   POINT 2. Не суди по числу файлов переводов: язык доступен, только если он включен в настройках приложения.
2. Найди на страницах этой задачи список языков интерфейса.
3. Если список устарел, поправь его в RU и EN и добавь строки в `docs/trace.md`. Другие разделы не трогай.
4. В `summary` напиши, какие языки добавились или убрались. Если набор не изменился или по источникам это
   не определить, так и напиши; во втором случае верни `needs_human`.

## Вид задания `release_notes`: Довести release notes

Выполняется последним, после всех остальных заданий. Черновик собран кодом автоматически из названий
задач и записей разработчиков: структура в нем правильная, а формулировки сырые. Твоя работа -
переформулировать, а не пересобрать. Открывай только файлы, названные в задании.

1. Перепиши каждую строку языком пользователя: что изменилось на экране. Убери названия компонентов,
   хуков, файлов. Смысл строки не меняй и ничего не добавляй: источник - только текст самой строки.
2. Одна строка на задачу. Не добавляй строк, которых нет в черновике.
3. У некоторых строк стоит пометка «ожидает решения». Это задачи, которые ты проверял в заданиях `decide`.
   Оставь строку, только если ты решил по этой задаче `doc`, `rn` или `langs`. Если решил `skip` или
   `screens`, или вернул `needs_human`, удали строку.
4. Сделай английский файл: тот же состав строк, перевод в стиле образца прошлого релиза.
5. Удали все служебные комментарии `<!-- ... -->` и первую строку с меткой черновика. Заголовок с версией
   и таблицу версий компонентов не меняй.
6. Если из строки непонятно, что изменилось для пользователя, не переписывай ее по догадке: оставь текст
   как есть и назови строку в `questions`.

В `files_changed` перечисли оба файла. `steps`, `evidence` и `edits` для этого задания не нужны.

Код проверит: число строк равно числу принятых задач и одинаково в обоих языках, комментариев не осталось,
заголовок и таблица не изменены.
