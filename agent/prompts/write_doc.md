## Что сделать: написать правку документации

Задача {{UNIT}} одобрена: изменение видит пользователь, документацию нужно поправить.

1. По патчам и текстам интерфейса выясни, что изменилось на экране: экран, элемент, было -> стало.
2. Найди место в рабочей копии `{{RESULT}}/MD_rus/docs`. Начни со страниц-кандидатов. Если раздел
   подключается через `{% include %}`, правь include-файл. Найди и другие упоминания старого названия
   или поведения по всей документации.
3. Внеси правку в RU, затем ту же по смыслу в `{{RESULT}}/MD_eng/docs`. Правка минимальная, в стиле
   соседних абзацев. Названия элементов бери дословно из текстов интерфейса нужного языка
   (`{{DATA}}/03_i18n_rows.json`, поле `new`). Названия продуктов - только переменными документации.
4. Если на странице есть скриншот затронутого экрана, поставь перед ним метку и добавь строку в
   `{{RESULT}}/screenshots.md`:

   ```markdown
   !!! warning "SCREENSHOT-TODO {{UNIT}}"
       Переснять: что именно.
       Причина: что изменилось.
   ```

5. На каждую правку добавь строку в `{{RESULT}}/trace.md`: задача, язык, файл, что изменено, правила.
6. Файл release notes не трогай: для него есть отдельное задание.

Если подходящего места нет или не хватает факта, текст не выдумывай: верни `needs_human` с вопросом.
