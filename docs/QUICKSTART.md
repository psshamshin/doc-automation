# Быстрый старт: от клонирования до сравнения

Подходит для любого агента, который запускается вручную из редактора (например, Copilot в VS Code).
Нужны Python 3.9+, git и редактор с агентом.

## 1. Забрать проект

```bash
git clone https://github.com/psshamshin/doc-automation.git
cd doc-automation
python3 -m unittest discover -s tests     # проверка, что все работает: в конце должно быть OK
```

## 2. Положить данные

В папку `input/` сложите архивы из GitLab как есть (тег -> Download zip):

- код фронтенда предыдущего релиза;
- код фронтенда нового релиза;
- документацию предыдущего релиза.

Документацию нового релиза от техписа сюда **не кладите**: агент не должен ее видеть. Держите ее вне
папки проекта до шага 6.

```bash
python3 -m pipeline versions              # что нашлось и какие версии определились
```

## 3. Собрать изменения

```bash
python3 -m pipeline collect
```

Если версия нового релиза определилась неверно: `python3 -m pipeline collect --release 2.4.0`.

По желанию: выполните в Jira запросы из `output/<версия>/jira_query.txt`, положите выгрузки (XML) в
`input/` и запустите `collect` еще раз.

## 4. Проверить решения

Откройте `output/<версия>/review.md`. У каждой задачи одна отметка `[x]`: «Принять», «Отклонить» или
«Агенту». Переставьте, где не согласны, и поставьте `Проверено: [x]` наверху.

## 5. Агент

```bash
python3 -m pipeline agent
```

Команда соберет для агента отдельную папку `output/<версия>/agent_workspace/`. В ней только задания,
рабочая копия документации и источники каждой задачи.

1. Откройте в редакторе **только эту папку** (Файл -> Открыть папку), а не весь проект. Иначе агент увидит
   лишнее: правила, код пайплайна, список доработок.
2. Откройте чат агента. Общие правила и порядок заданий записаны в `AGENTS.md` в этой папке: большинство
   агентов читают этот файл сами. Если ваш не читает, прикрепите его к первому сообщению.
3. Дайте агенту задания из `tasks/` в порядке из `AGENTS.md`: по одному или все сразу одним сообщением
   («Выполни задания из папки tasks по порядку из AGENTS.md»). Все задания готовы сразу, второго круга нет.
   Не задавайте агенту вопросов о других файлах: он обязан отвечать только по источникам задания.
4. Вернитесь в терминал проекта и запустите:

```bash
python3 -m pipeline agent
```

Команда проверит ответы, цитаты и сами правки и перенесет принятое в `output/<версия>/result/`. Если в
журнале есть задания «не подтверждено», дайте агенту только их и запустите команду еще раз.

Следить за работой агента можно по файлу `progress.md` в его папке: он дописывает туда каждый шаг.

Журнал: `output/<версия>/agent/summary.md`. Там же время по каждому заданию. В нем по каждому заданию видно, принято оно или нет и почему.

| Состояние | Что делать |
| --- | --- |
| принято | Ничего |
| принято, нужен второй круг | Агент сомневается в выводе, причина в журнале. Запустите `python3 -m pipeline agent` еще раз: появится задание второго круга. Свою задачу можно отправить так: `--recheck GUI-4104 --note "что проверить"` |
| ждет агента | Дать задание агенту |
| не подтверждено | Агент сослался на то, чего нет в источниках, или не прочитал `AGENTS.md`. Причина записана в журнале. Дайте задание заново: правки отклонены, страницы возвращены |
| нужен человек | Агент не нашел факта в источниках. Его вопросы записаны в журнале |

## 6. Сравнить с документацией техписа

Только после того, как агент закончил:

```bash
python3 -m pipeline compare --reference /путь/к/документации/техписа
open output/<версия>/compare/compare.html
```

На странице три колонки: было, пайплайн, техпис. Перед следующим запуском агента удалите папки
`output/<версия>/reference` и `output/<версия>/compare`.

## Если что-то пошло не так

| Сообщение | Что делать |
| --- | --- |
| `нужно ровно два варианта кода фронтенда` | В `input/` не два архива кода или они одной версии |
| `решения не проверены` | Поставьте `Проверено: [x]` в `review.md` |
| `нужна ровно одна отметка [x]` | В строке задачи в `review.md` отмечено ноль или две колонки |
| `не удалось определить версию нового релиза` | Добавьте `--release <версия>` к `collect` |
