# Правила

Действующие правила. Код - `pipeline/units.py`, `confidence.py`, `checks.py`; настройки (слова, шаблоны, признаки
продуктов) - `knowledge/rules.json`. Правила применяются по порядку групп: А, Б, В, Г, Д, Е, И. Группа К работает
отдельно, по всей документации. Номера правил постоянные: пропущенный номер значит, что правила нет.

## А. Границы релиза

| ID | Правило |
| --- | --- |
| А1 | Границы задают версии интерфейса (point-ui): меньшая - предыдущий релиз, большая - новый. Версия читается из `apps/point/package.json` в двух папках с кодом. |
| А2 | Из списка изменений берутся версии строго выше нижней границы и не выше верхней, включая патчи. |
| А3 | Остальные версии не учитываются. |

## Б. Задачи

| ID | Правило |
| --- | --- |
| Б1 | Записи списка изменений группируются по номеру задачи (`GUI-123` в начале записи). Задача - единица работы. |
| Б2 | К задаче привязываются измененные файлы кода, на которые указывают ее записи: по тегам (`[monokit][features/x]` -> `packages/monokit/features/x`), по именам компонентов и хуков в тексте. Файлы другого продукта (`.point3.` в имени, папки `apps/point3`, `apps/clementine`, `apps/luna`) в доказательства не входят. |
| Б3 | Запись без номера задачи - отдельная задача `NOTASK:<версия>#<номер>`. |

Запись **значимая**, если она не про другой продукт (метка в тексте или теге), не тестовая (тег `cypress`, `e2e`, `tests`,
`vitest`) и не техническая (слова «рефакторинг», «перенесен», «зависимости» и подобные; запись о переносе кода со
ссылкой на код техническая всегда). Все доказательства по задаче считаются только по значимым записям.

## В. Продукт

Первое сработавшее правило решает.

| ID | Правило | Решение |
| --- | --- | --- |
| В1 | В названии задачи в Jira метка `[point]` | POINT 2 |
| В7 | Все записи задачи про другой продукт | отбросить |
| В3 | Все файлы значимых записей в `apps/point/` | POINT 2 |
| В4 | Все файлы значимых записей в приложениях других продуктов | отбросить |
| В5 | Хотя бы один файл значимых записей достижим из `apps/point/src` по графу импортов | POINT 2 |
| В6 | Файлы есть, но ни один не достижим из `apps/point` | отбросить |
| В2 | В Jira метка другого продукта (`point3`, `clementine`, `luna-ui`, `luna`) или он назван в тексте названия, **и** кода POINT 2 нет | отбросить |
| В9 | Файлов нет или они только у записей другого продукта | передать агенту |

Если Jira называет другой продукт, а код использует POINT 2, задача остается и получает пометку И9. Метки не о продуктах
(`[shared]`) не учитываются.

## Г. Видимость для пользователя

Оцениваются значимые записи и их файлы. Первое сработавшее правило решает.

| ID | Правило | Решение |
| --- | --- | --- |
| Г4 | Нет значимых записей; либо все файлы - тесты, сборка, типы, моки | не видно |
| Г1 | Изменились тексты интерфейса в файлах задачи (кроме текстов, которые используют только файлы другого продукта) | видно |
| Г2 | Изменены навигация, роуты или права; либо в записях слова интерфейса | видно |
| Г3 | Все файлы - стили; либо все записи - исправления со словами «стили», «отступы», «шрифт», «цвет», «анимация» | только оформление |
| Г5 | Слова интерфейса только в записях-исправлениях | видно |
| - | Ничего не сработало | передать агенту |

## Д. Вид изменения и решение

Вид изменения код определяет по порядку; первое сработавшее решает.

| ID | Вид | Признак |
| --- | --- | --- |
| Д9 | Локализация | Запись с тегом `i18n` и словами «локал» или «язык»; либо появился каталог новой локали |
| Д3 | Меню, навигация, поведение | Тег `navigation`, путь `/navigation/` или `/routes`, слово «меню»; также вид по умолчанию |
| Д6 | Права и роли | Путь `/permissions/`, слова «права доступа», «роли» |
| Д7 | Удаление | Запись «Удалено» или слова «удален», «убран» в записи не из «Исправлено» |
| Д5 | Поля, валидация | Слова «валидац», «обязательн», «placeholder», «по умолчанию», «максимальн» |
| Д4 | Переименование | Изменился текст при том же ключе перевода |
| Д2 | Новая функция | Запись «Добавлено» без исправлений |
| Д8 | Исправление ошибки | Все значимые записи из «Исправлено» |
| Д1, Д10, Д11 | Новый раздел, администрирование, несовместимое изменение | Кодом не определяются: версия компонента заменяется отдельно, остальное решает агент |

| Видимость | Вид | Решение |
| --- | --- | --- |
| другой продукт или не видно | любой | отбросить |
| только оформление | любой | проверить скрины |
| не определена | любой | передать агенту |
| видно | Д8 | строка release notes (`rn`) |
| видно | Д9 | строка release notes и проверка списка языков (`langs`) |
| видно | остальные | правка документации и строка release notes (`doc`) |

## Е. Место в документации

| ID | Правило |
| --- | --- |
| Е1 | Страница для части интерфейса задана заранее в `knowledge/doc_map.json` (по пути файла или тегу, затем по словам). Это подсказка агенту. |
| Е2 | Если текст лежит в `includes/`, правится include-файл. |
| Е3 | Устаревшие названия ищутся по всему релизу, без привязки к задачам: тексты, которые были в интерфейсе предыдущей версии и исчезли, ищутся в документации дословно и в кавычках. Для каждого указаны файлы кода, где название использовалось. |
| Е4 | Нет подходящей страницы или факта - правка не делается. |

## И. Достоверность решения

Низкая достоверность (по умолчанию задача уходит агенту, человек может изменить) при любом из критериев:

| ID | Критерий |
| --- | --- |
| И1 | Продукт не определен (В9) |
| И2 | Видимость не определена |
| И3 | Видимость определена только по словам в записи, и к значимым записям не привязан ни один файл, который использует приложение |
| И4 | Все изменившиеся тексты интерфейса привязаны и к другим задачам, и ни один не назван в записях этой задачи |
| И5 | Продукт POINT 2, но не меньше половины файлов значимых записей приложение не использует |
| И9 | Справка, достоверность не снижает: Jira относит задачу к другому продукту, а решение принято по коду |

## К. Сквозные проверки документации

Не привязаны к задачам, выполняются кодом по рабочей копии документации. Те же проверки идут по документации прошлого
релиза: у находки отмечено, появилась она в этом релизе.

| ID | Правило |
| --- | --- |
| К1 | Битые ссылки: страница или якорь, которых нет; подключаемый файл, которого нет. Внешние ссылки не проверяются. |
| К2 | Названия продуктов текстом: «LUNA» и «VisionLabs» вне переменных документации. Блоки кода и release notes не проверяются. |
| К3 | Расхождения языков: страницы нет в одном из языков; разное число разделов, картинок, подключаемых файлов, примечаний; разные версии компонентов. Число строк таблиц не сравнивается. |
| К4 | Картинка, файла которой нет; картинка без ссылок; файл из `includes`, не подключенный ни одной страницей. Путь к картинке считается так, как его собирает сайт. |
| К5 | Скриншоты к проверке: изменился текст раздела страницы - скриншоты раздела (если их нет, то раздела выше, до всей страницы). Страница не менялась - скриншоты прежние. По задаче «только оформление» - все скриншоты ее страниц. Замена номера версии изменением экрана не считается. |
| К6 | Исправление находок. После всех правок код повторяет К1, К2, К3, К4 и отдает агенту (задание `checks_fix`) находки, которые появились в этом релизе или лежат на страницах, правленных в этом релизе (не более 40). Остальные находки были до релиза и не правятся. Картинки без ссылок и страницы, которых нет в одном из языков, правкой текста не исправляются. Правки проверяются как все остальные; кроме того, код отклоняет ссылку на страницу, которой нет, и переменную, которой нет в документации. |

## Ж. Написание (агент)

| ID | Правило |
| --- | --- |
| Ж1 | Сначала правки RU, затем те же по смыслу EN. Другие языки не трогаются. |
| Ж2 | Названия элементов интерфейса - дословно из текстов интерфейса новой версии, в кавычках. Код отклоняет название, которого там нет. |
| Ж3 | Названия продуктов - переменными страницы, не «LUNA» и «VisionLabs» текстом. |
| Ж4 | Факты - только из источников задания; каждый вывод подтвержден дословной цитатой. Нет факта - статус `unknown`, правка не делается. |
| Ж5 | Правка минимальная: один фрагмент, до 30 строк нового текста, без комментариев. |
| Ж6 | Правки вносит код после проверки и сам ведет `trace.md`. Агент файлы не меняет. |
| Ж7 | Если текст лежит в `includes/`, правится include-файл. |
| Ж8 | Release notes: код собирает структуру по образцу прошлого релиза (заголовок, таблица версий, разделы, метки); агент дает по одной формулировке RU и EN на задачу. «Исправленные ошибки» - задачи, где все значимые записи из «Исправлено» или решение `rn`. |
| Ж9 | Если агент решил `doc` или `langs` в задании `decide` и правок в ответе не дал, код создает задание `write_doc` в том же запуске. |

## З. Скриншоты

| ID | Правило |
| --- | --- |
| З1 | Список скриншотов к проверке строит код (К5): `result/screenshots.md`. Агент ими не занимается и меток в текст не ставит. |
| З2 | Скриншоты снимает человек, по списку. Что изображено на картинке, код не знает. |
