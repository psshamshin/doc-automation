# Как проверить результат

Команда `collect` не использует случайность, время и сеть. Одинаковые входные данные и одинаковый код
дают одинаковые файлы байт в байт. Ниже - как в этом убедиться.

## 1. Проверка без входных данных (2 секунды)

```bash
python3 -m py_compile pipeline/*.py tests/*.py
python3 -m unittest discover -s tests
```

Ожидается: `Ran 159 tests ... OK`. Тест `test_rerun_is_identical` запускает сбор на придуманных данных
дважды и сравнивает контрольные суммы всех результатов. Тесты `AgentTest` проверяют папку агента,
проверку ответов и внесение правок кодом с заглушкой вместо агента.

Полный прогон на придуманных данных:

```bash
rm -rf output/demo
python3 -m pipeline collect tests/data/demo
shasum -a 256 output/demo/report.md output/demo/review.md
```

Ожидается:

```
d2b8f289cc42c45024ba64fc3f46915a3eef9a06080ff705b3aa22a81d0fdfaa  output/demo/report.md
0d3b606d43990d1bf4660a27ab2e421c9091dc3f1f516e6aa8d68e0b8208b075  output/demo/review.md
```

Эти данные лежат в репозитории, поэтому суммы должны совпасть на любой машине. Те же файлы задача Tests
сохраняет как артефакт `demo-review`.

## 2. Проверка на реальных данных релиза 2.3.0

Нужны входные данные релиза 2.3.0 в `input/` или в `input/2.3.0/` (см. README, раздел 5), без выгрузки Jira.
Если набор данных в `input/` один, имя в командах можно не писать.

```bash
python3 -m pipeline versions 2.3.0
```

Ожидается:

```
набор данных:                    2.3.0
новый релиз:                     2.3.0  (база знаний: point-ui 2.11.0 = релиз 2.3.0)
дата релиза:                     05.10.2026
документация предыдущего релиза: 2.2.0
интерфейс:                       2.9.4 -> 2.11.0
файл release notes:              230.md (образец: 220.md)
```

Сбор:

```bash
python3 -m pipeline collect 2.3.0 --force
shasum -a 256 output/2.3.0/report.md output/2.3.0/review.md
```

Флаг `--force` нужен, чтобы файл проверки и рабочая копия документации были созданы заново. Не
используйте его, если в `output/2.3.0/` уже есть ваши отметки или правки агента.

Ожидается:

```
82d0f4f4f4b066f52f3f9dcff4d42b4efd0eac42e63fb40c0b8971f2c926f206  output/2.3.0/report.md
90bee61f2398e81002c2b5db70f80807a533b328a87562f7d4a535c6fcbebd02  output/2.3.0/review.md
```

Суммы верны для кода и правил из коммита, в котором этот файл менялся последний раз, и для запуска без
выгрузки Jira. После правки правил или загрузки задач Jira суммы изменятся: тогда сверяйте таблицу решений
(ниже) и обновите суммы здесь.

## 4. История прогонов

Отчет первого прогона сохранен локально: `output/2.3.0/report_run1.md`.

```bash
diff <(grep '^| GUI' output/2.3.0/report_run1.md | sort) <(grep '^| GUI' output/2.3.0/report.md | sort)
```

| Задача | Прогон 1 | После изменений 1-4 | После изменений 7-9 | Ожидалось |
| --- | --- | --- | --- | --- |
| GUI-4106 | в доку + RN, Д3, 18 страниц | RN + проверить список языков, Д9 | без изменений | только строка RN про языки |
| GUI-4134 | в доку + RN, Д7 | RN + проверить доку, Д8 | без изменений | только RN, Д8 |
| GUI-4057 | в доку + RN, Д3 | RN + проверить доку, Д8 | проверить скрины, Г3 | отбросить или проверить скрины |

Решения правил по остальным 19 задачам не менялись ни в одном прогоне. Изменение 9 сократило число задач
с низкой достоверностью с 9 до 6. Замен названий (изменение 12) в релизе 2.3.0 код не нашел: ни одно
переименование не названо в записях задач и не стоит в документации в кавычках.
