# Как проверить результат

Команда `collect` не использует случайность, время и сеть. Одинаковые входные данные и одинаковый код
дают одинаковые файлы байт в байт. Ниже - как в этом убедиться.

## 1. Проверка без входных данных (2 секунды)

```bash
python3 -m py_compile pipeline/*.py tests/*.py
python3 -m unittest discover -s tests
```

Ожидается: `Ran 82 tests ... OK`. Тест `test_rerun_is_identical` запускает сбор на придуманных данных
дважды и сравнивает контрольные суммы всех результатов. Тесты `AgentTest` проверяют обертку агента с
заглушкой вместо настоящего агента.

Полный прогон на придуманных данных и его контрольные суммы:

```bash
rm -rf output/demo
python3 -m pipeline collect tests/data/demo
shasum -a 256 output/demo/report.md output/demo/draft.md output/demo/validation.txt
```

Ожидается:

```
d2b8f289cc42c45024ba64fc3f46915a3eef9a06080ff705b3aa22a81d0fdfaa  output/demo/report.md
d24b20cd61c451b970d4ec41cf7675bc5ddfb3e96a82cf2cd29c3f69ed28e561  output/demo/draft.md
b27d28289c74f7e6bdbccb3e854e3dcb4da44656b91a3c8d7923b19d6f8321b4  output/demo/validation.txt
```

Эти данные лежат в репозитории, поэтому суммы должны совпасть на любой машине. Те же три файла задача
Tests сохраняет как артефакт `demo-draft`.

## 2. Проверка на реальных данных релиза 2.3.0

Нужен набор данных `input/2.3.0/` (см. README, раздел 5). Папка `jira-tasks` пустая.

```bash
python3 -m pipeline versions 2.3.0
```

Ожидается:

```
набор данных:                    2.3.0
новый релиз:                     2.3.0  (база знаний: point-ui 2.11.0 = релиз 2.3.0)
дата релиза:                     05.10.2026
документация предыдущего релиза: 2.2.0
интерфейс:                       2.9.4 -> 2.11.0
файл release notes:              230.md (образец: 220.md)
```

Сбор:

```bash
python3 -m pipeline collect 2.3.0 --force
shasum -a 256 output/2.3.0/report.md output/2.3.0/draft.md output/2.3.0/validation.txt
```

Флаг `--force` нужен, чтобы файл проверки и рабочая копия документации были созданы заново. Не
используйте его, если в `output/2.3.0/` уже есть ваши правки или правки агента.

Ожидается:

```
cd296449d53663a1133ba12116cdd2aadcad6f1cdd0200c291559e030102300a  output/2.3.0/report.md
66d6ae305608410583311e44149c553847cca8da9b7a5fe03b18d8163da3c8f1  output/2.3.0/draft.md
b3d02bbb639faff3badca2bd159ad0bd75ca7e2641fae3cb321a323620499768  output/2.3.0/validation.txt
```

Сумма `report.md` та же, что была до перестройки проекта: решения правил не изменились.

Суммы верны для кода и правил из коммита, в котором этот файл менялся последний раз, и для пустой папки
`jira-tasks`. После правки правил или загрузки задач Jira суммы изменятся: тогда сверяйте таблицу решений
(ниже) и обновите суммы здесь.

## 4. История: прогон 1 и прогон 2 (исправление правил)

Отчет первого прогона сохранен локально: `output/2.3.0/report_run1.md`.

```bash
diff <(grep '^| GUI' output/2.3.0/report_run1.md | sort) <(grep '^| GUI' output/2.3.0/report.md | sort)
```

| Задача | Прогон 1 | Прогон 2 | Ожидалось |
| --- | --- | --- | --- |
| GUI-4106 | в доку + RN, Д3, 18 страниц | RN + проверить список языков, Д9, 1 страница | только строка RN про языки, Д9 |
| GUI-4134 | в доку + RN, Д7, 3 страницы | RN + проверить доку, Д8, 1 страница | только RN, Д8 |
| GUI-4057 | в доку + RN, Д3, 3 страницы | RN + проверить доку, Д8, 2 страницы | отбросить или проверить скрины |

Остальные 19 задач между прогонами не изменились. GUI-4057 не отброшена правилами, но теперь у нее низкая
достоверность по критерию И5, и ее проверяет агент.
