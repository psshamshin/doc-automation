# Шаг 4. Место в доке

**Вход:** `runs/<release>/07_analysis.json`, `runs/<release>/05_units.json` (`doc_candidates`, `doc_mentions`),
`runs/<release>/06_docs_index.json`, тексты `runs/<release>/output/MD_rus/docs`.
**Выход:** `runs/<release>/08_plan.json` по схеме `schemas/plan.schema.json`.

## Что сделать

Для каждой единицы с `in_doc: true` из `07_analysis.json`:

1. Начать с `doc_candidates` (карта «код → раздел», правило Е1). Это подсказка: подтвердить или отклонить.
2. Найти конкретное место: файл, заголовок, номер строки или цитату абзаца/строки таблицы.
3. Если раздел подключается через `{% include %}` — местом правки считать include-файл (Е2).
4. Найти все упоминания старого названия или поведения по всей доке RU и EN (Е3):
   `doc_mentions` + собственный поиск по `output/`. Каждое — отдельное действие `replace` или `check`.
5. Определить картинки, которые показывают затронутый экран (`images` в индексе доки), и действие для них
   по правилам З1–З4.
6. Если места нет и непонятно, куда добавлять — действие `needs_decision` с вариантами (Е4).

Действия: `insert` (новый текст), `replace` (замена фрагмента), `delete`, `check` (проверить человеку),
`screenshot` (метка SCREENSHOT-TODO), `needs_decision`.

Один план на RU; EN — те же файлы с теми же действиями (структура доки совпадает), отличия указать явно.
