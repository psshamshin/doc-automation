# Шаг 5. Правки доки RU → EN

**Вход:** `runs/<release>/08_plan.json`, `runs/<release>/07_analysis.json`, строки UI `03_i18n_rows.json`.
**Выход:** изменённые файлы в `runs/<release>/output/MD_rus/docs` и `MD_eng/docs`,
строки в `runs/<release>/output/trace.md` и `runs/<release>/output/screenshots.md`.

## Порядок

1. Выполнить план для RU. Каждая правка минимальна (Ж5), стиль соседних абзацев (Ж4).
2. Названия элементов интерфейса — дословно из `03_i18n_rows.json` → `new`, локаль `ru` (Ж2).
3. Продукты и компоненты — только переменными доки (Ж3).
4. Для затронутых скринов — метка перед ссылкой на картинку (формат в AGENTS.md) и строка в `screenshots.md`.
5. Повторить для EN: смысл тот же, названия из локали `en`, кавычки "…".
6. На каждую правку — строка в `trace.md`: задача, язык, файл, что изменено, правила.
7. Если в источниках не хватает факта — не писать текст, а оставить в файле HTML-комментарий
   `<!-- TODO GUI-xxxx: вопрос -->` и строку в `trace.md`.

## Самопроверка перед завершением

- `grep -rn "LUNA\|VisionLabs" ` по изменённым строкам — новых жёстких упоминаний нет.
- Все ссылки на картинки ведут на существующие файлы базовой доки (или новые имена записаны в `screenshots.md`).
- Markdown не сломан: таблицы с тем же числом колонок, admonition с отступом 4 пробела.
- Изменены только файлы из плана.
