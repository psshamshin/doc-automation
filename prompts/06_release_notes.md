# Шаг 6. Release notes

**Вход:** `runs/<release>/07_analysis.json` (поля `release_note`), `config/release-<release>.json`
(`release_notes`, `component_versions`), предыдущий файл `output/MD_rus/docs/release-notes/<previous>`.
**Выход:** `runs/<release>/output/MD_rus/docs/release-notes/<file>` и то же в `MD_eng`, плюс запись в `.pages`
каталога release-notes, если она там ведётся.

## Структура

Скопировать структуру предыдущего файла: заголовок с номером версии, дата выпуска, таблица версий компонентов,
разделы «Изменения» и «Исправленные ошибки» (точные названия — как в предыдущем файле, для EN — как в EN-файле).

- Версии компонентов: взять таблицу из предыдущего файла и заменить значения из `component_versions`.
  Остальные версии оставить и пометить в `trace.md` «проверить версию» — во фронтовых артефактах их нет.
- «Изменения»: одна строка на единицу с классом Д1–Д7, Д9, Д11. Сгруппировать по разделам продукта, как в
  предыдущих release notes, если там есть группировка.
- «Исправленные ошибки»: единицы класса Д8.
- Язык пользователя, без названий компонентов, хуков, файлов и номеров задач (Ж8).
- Breaking change (Д11) — отдельной пометкой.
